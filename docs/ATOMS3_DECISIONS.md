# AtomS3 Decisions Log

One row per non-trivial design decision specific to the AtomS3 variant.
Each row must cite at least one reference from
[`ATOMS3_REFERENCE_GROUNDING.md`](ATOMS3_REFERENCE_GROUNDING.md) (`R1`–`R10`)
or be flagged `unsupported-by-references` and revisited.

| Date       | ID    | Decision                                                                                                  | Rationale                                                                                                                                                                  | Refs        |
|------------|-------|-----------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------|
| 2026-05-22 | D-001 | Add AtomS3 as a build variant in the same project (not a new repo).                                       | Core BLE/protocol/motion logic is shared; existing multi-target structure (Plus2 / Plus 1.1 / StickS3) already supports per-board HAL.                                     | R1, R3      |
| 2026-05-22 | D-002 | First bring-up uses ST7789 driver (existing) for the AtomS3 panel; switch to gc9a01 driver if needed.     | The StickS3 HAL already has a working ST7789 init. Many GC9107 panels speak the same SPI command subset. esp-bsp uses gc9a01 for AtomS3, so the gc9a01 path is the fallback. | R4, R5, R6  |
| 2026-05-22 | D-003 | Disable SPIRAM in the AtomS3 sdkconfig defaults.                                                          | AtomS3 (ESP32-S3FN8) has no PSRAM; the StickS3 sdkconfig had OPI PSRAM enabled and would fail to init.                                                                     | R1, R3      |
| 2026-05-22 | D-004 | Single-button input model: short press cycles screens, long press is the contextual action.              | AtomS3 only has one user-accessible button (the screen). User-approved flow during planning.                                                                               | R1          |
| 2026-05-22 | D-005 | Reduce UI to two screens (`BT`, `AUTO`) with text-first layout for 128 × 128.                              | The existing 6-screen icon flow does not fit on 128 × 128; user explicitly asked for "BT screen and function" + "GPS / mode" only.                                          | R1, R4      |
| 2026-05-22 | D-006 | Skip M5PM1 PMIC code path for AtomS3.                                                                      | AtomS3 has no PMIC; it uses a fixed SY8089 5 V → 3.3 V regulator. Power-button-hold shutdown is also out of scope.                                                          | R1          |
| 2026-05-22 | D-007 | Reuse the existing UART NMEA GPS parser; only change pins (`TX=G2`, `RX=G1`) for AtomS3.                  | The parser is already proven on StickS3; the change is wiring-only on AtomS3 (HY2.0 PORT.A → G2/G1).                                                                       | R8, R9      |
| 2026-05-22 | D-008 | Drop icons, nav dots, and the instruction strip on the AtomS3 UI; text-only.                              | User feedback during first bring-up: icons were not desired; nav dots eat scarce vertical space on 128 × 128. R12 (one hero per screen, no chrome) supports this.          | R12, R13    |
| 2026-05-22 | D-009 | Use a 3-tier typographic scale on AtomS3: HERO (scale 3, 24 px), VALUE (scale 2, 16 px), LABEL (scale 1, 8 px). | Miller's Law per R13: more than ~3 active sizes per zone reduces legibility. R12 (BRUTAL) uses the same 3-tier hierarchy.                                                  | R11, R12, R13 |
| 2026-05-22 | D-010 | Use `M5_TRUE_*` color aliases for all AtomS3 paint calls (not `M5_COLOR_*`).                              | The AtomS3 panel is wired BGR; the legacy `M5_COLOR_*` constants render with R/B swapped on this panel. The `M5_TRUE_*` aliases already encode the swap.                  | R4          |
| 2026-05-22 | D-011 | One accent color per state (red REC / green ONLINE / yellow WAIT or CONNECTING); everything else white or dim grey. | Reduces gross-color reports. Three independent cues per state (color + word + position) per R13 keep the state legible even if the panel BGR swap regresses.               | R13         |
| 2026-05-22 | D-012 | No full-screen clear during steady-state updates on AtomS3 — partial diff-redraws only.                    | The blinking the user saw was the existing `m5stickc_plus2_display_fill_rect(0,0,W,H,...)` cycle. The AUTO partial-update cache pattern is extended to BT for AtomS3.       | R12         |
| 2026-05-22 | D-013 | Hard-clip every text draw to a margin so labels can never wrap or run off the AtomS3 panel.                | User reported "words running off the edges". The font helper's auto-wrap behavior pushes text to a new line on overflow; on 128 × 128 we want truncation, not wrap.        | R13         |
